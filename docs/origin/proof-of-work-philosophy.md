# Proof of Work Philosophy

기록 시점: 2026-09-30 / STEP -1 — Origin

이 프로젝트에서 Proof of Work는 완성된 소스 코드와 함께, 답을 모르는 문제에서 어떻게 답을 찾아갔는지를 증거로 남기는 것을 뜻한다. 현재 기록하려는 흐름은 다음과 같다.

Problem → Observation → Measurement → Decomposition → Evidence → Hypothesis → Experiment → Failure / Revision → Action → Result → Verification → Reflection

이 흐름은 모든 작업이 한 번에 순서대로 진행된다는 뜻은 아니다. 관찰이나 측정으로 되돌아갈 수 있고, 실험에서 가설이 틀렸음을 알게 될 수도 있다. 실제로 일어난 순서와 당시의 판단을 기록한다.

## 기록 원칙

- 관찰한 사실, 측정한 값, 해석, 가설과 질문을 구분한다.
- 실행하려는 실험과 실제로 실행한 실험을 구분한다.
- 결과를 기록할 때에는 가능한 범위에서 조건과 근거를 함께 남긴다.
- 실패한 가설과 시행착오를 지우지 않고, 무엇 때문에 수정했는지 기록한다.
- 아직 모르는 내용은 모른다고 적는다. 나중에 알게 된 내용을 처음부터 알고 있었던 것처럼 과거 기록에 덧씌우지 않는다.
- 과거 경험을 나중에 기록한다면 회고임을 밝히고, 당시에 남긴 증거와 현재의 기억을 구분한다.

## Git history와 Journal

Git history도 작업증명의 일부로 다룬다. 가능하면 의미 있는 사고 변화, 실험, 구현과 검증 단위로 commit을 남긴다. 과거 commit을 지나치게 정리해 시행착오가 없었던 것처럼 만들지 않는다.

JOURNAL.md에는 시점별 질문과 판단의 변화를 쌓는다. 이후 생각이 바뀌면 새 Entry에서 이전 생각과 변경 이유를 연결한다. 기록을 얼마나 세밀하게 남기는 것이 유용한지는 작업하면서 조정한다.

증거 공개는 기밀 보호 범위 안에서 이루어진다. 회사 식별 정보, 내부 데이터, 보안정보와 실제 회사 소스 코드를 공개하지 않는다. 일반화하거나 추상화한 자료는 그 성격을 밝히며, 실제 운영 환경의 직접 증거인 것처럼 표현하지 않는다.
